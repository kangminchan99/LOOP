# 게시글 목록 오프라인 캐시

## 동작과 범위

- Android/iOS의 게시글 목록을 Drift(SQLite)에 저장한다. 상세 본문·이미지·검색 결과는 이 캐시의 대상이 아니다.
- 앱 시작 시 유효한 캐시를 먼저 표시하고 첫 서버 페이지로 교체한다. 온라인 새로고침 성공 시 이전 캐시 전체를 교체하므로 기존 200개가 첫 페이지 20개로 줄어들 수 있다.
- 서버에서 첫 페이지부터 연속 조회한 앞쪽 최대 200개만 저장한다. 화면 목록은 200개 이후에도 기존 커서로 계속 조회한다.
- 조회 흐름의 최초 서버 응답 시각부터 7일 동안 유효하다. 다음 페이지를 저장하거나 제목을 수정해도 만료 시각은 연장하지 않는다. 만료 데이터는 캐시를 읽을 때 삭제한다.
- 디스크 캐시에 서버 커서를 합성하지 않는다. 캐시만 표시 중이면 추가 조회를 막고, 재시도 시 서버 첫 페이지부터 시작한다.
- 통신 실패 시 기존 목록과 재시도 버튼을 보여준다. 추가 페이지 실패는 같은 커서로 재시도한다. 서버 500 응답을 오프라인으로 표시하지 않는다.
- 앱 재개, 새로고침 버튼, 당겨서 새로고침으로 최신 목록을 조회한다. 앱이 종료된 상태에서 백그라운드 동기화하지 않는다.
- 서버 수정/삭제 성공 후 캐시 제목 갱신/행 삭제를 수행한다. 서버 실패 시 캐시는 유지한다. 다른 사용자의 변경은 다음 서버 조회 때 반영한다.
- 명시적 로그인/회원 계정 변경/로그아웃/인증 reset 시 캐시를 비우고 목록 Provider를 새로 생성한다. 자동 로그인 복원만으로는 캐시를 비우지 않는다. 현재 캐시는 공개 게시글 목록용이며 사용자 비공개 데이터를 추가하려면 영속적인 사용자별 저장 구분이 필요하다.

## 경합과 성능

- DB 실행은 drift_flutter의 전용 isolate를 사용한다. 연결은 공용 Provider에서 한 번 생성한다.
- 로컬 읽기/저장/삭제는 순서대로 수행하고 스냅샷 교체는 트랜잭션과 batch로 처리한다.
- 세션 번호와 캐시 변경 번호로 로그아웃·수정·삭제 전에 시작한 요청의 저장을 거부한다.
- Notifier의 요청 번호와 mounted 검사로 폐기된 화면 및 오래된 요청의 상태 변경을 막는다.
- 최대 200행만 DB에서 읽고 저장한다. ListView는 항목을 필요할 때 생성한다. 화면의 누적 목록 메모리까지 200개로 제한되는 것은 아니다.
- SQLite의 초 단위 시간 저장으로 정렬이 바뀌지 않도록 별도 position 컬럼으로 서버 순서를 보존한다. schemaVersion 2로 v1 캐시를 안전하게 비우고 업그레이드한다.
- 캐시 저장 실패는 서버 목록 조회 성공을 실패로 바꾸지 않으며 로그로 기록한다.

## 확인 방법

1. 온라인에서 11페이지(각 20개)를 조회한다. 화면 220개, DB 200개 이하를 확인한다.
2. 앱을 종료하고 네트워크를 끈 후 다시 연다. 저장된 목록과 연결 실패 안내를 확인한다.
3. 연결 복구 후 재시도하면 최신 첫 페이지가 나타나야 한다.
4. 수정/삭제 성공 후 오프라인으로 재시작해 이전 제목/삭제한 글이 남지 않는지 확인한다.
5. 요청 진행 중 로그아웃하고 다른 계정으로 로그인하여 이전 요청 결과가 돌아오지 않는지 확인한다.
6. 실제 기기 profile 모드에서 빠른 스크롤과 캐시 저장 중 프레임 시간을 측정한다. 단위 테스트 통과만으로 프레임 드랍이 없다고 보장하지 않는다.

```bash
flutter test test/features/post
flutter analyze --no-pub
flutter run --profile
```

웹에서 영속 캐시를 활성화하려면 해당 drift 버전에 맞는 WASM/worker 및 DriftWebOptions 설정이 추가로 필요하다. 현재는 DB 실패를 처리하고 서버 조회를 계속한다.
